# Word 稿件格式自动规范化 V5 — 内部架构

V5 保持最终交付为单文件 HTML，但内部从“顺序堆叠函数”改为分层流水线：

1. `DocxContext`：统一持有 ZIP、document.xml、body、选项、统计、原始快照。
2. `RuleEngine`：按 `package → structure → placement → format → post` 五个阶段执行规则。
3. `RULES`：每项规则有稳定 ID、名称、阶段、启用条件和执行函数。以后新增规则不再直接改主流程。
4. `ChangeRecorder`：记录每条规则执行前后的统计差异，用于编辑端查看“本次工具做了什么”。
5. `IntegrityGuard`：处理前后核对表格、图片、公式、OLE/对象、域、书签、超链接等受保护结构数量；出现减少即进入审核警告，高风险对象减少时提高风险等级。
6. `AuditEngine`：独立负责图表正文引用、连续引文残留、参考文献序号、收稿日期、末级标题、作者简介对齐、颜色残留等质检。
7. `UIController`：只负责上传、运行、下载和展示，不再承担 DOCX 业务规则。

## 当前规则阶段

- package：页面/节版式
- structure：公式编号保护、分隔线清理、元数据归位、图表题拆分
- placement：图片和表格安全归位
- format：正文、标题、标签、引文、图表引用等确定性格式
- post：显式颜色归黑、numbering/styles 等辅助部件处理

## 规则边界

自动修改只用于已从正确样本中确认的稳定规则。普通数值范围、单位数值、论文技术内容、正文缺失的“如图 n 所示”等不自动创造或改写，只进入质检提醒。

## 后续开发约束

新增规则优先作为 RULES 中的新规则，而不是继续在主流程中追加 if/regex。任何可能删除或重建 OOXML 对象的规则都必须经过 IntegrityGuard；图、表、公式、域、书签、MathType/OLE 属于默认保护对象。
